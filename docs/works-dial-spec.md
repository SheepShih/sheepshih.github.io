# Works の回転ダイヤルと暗号化 実装仕様

Works (2022~) の電話のダイヤルを回して番号を入力し、正しければ中身を表示する。
電話をタップするとシーンが2.4倍に拡大し、ダイヤルを回せるようになる。登場の「溶ける」エフェクトの途中や始まる前でもタップでき、そのときはエフェクトをすぐ終えて拡大する。
拡大中に外をタップすると元に戻る（Esc キーでも戻る）。
正解すると「つながった」音のあと、拡大を戻してダイヤルを消し、店内（郵便ロッカーの受付）の画像に、登場時と同じ「溶ける」エフェクトで切り替わる。
店内の画像は暗号化された中身（`private/works-content.html` に data URI で埋め込み）に入っているので、番号なしでは見られない。画像を変えたら `tools/encrypt-works.py` で暗号化し直す。
切り替えは `works-dial.js` が出す `works-unlocked` イベントを `works.html` が受けて行う。
店内では、鍵(札)の掛かった私書箱5つ(1段目の右から2つ目・2段目の真ん中・3段目の左から2つ目と右から2つ目・4段目の真ん中)をタップすると、鍵が90度回って(カチッ)、扉が右の蝶番を軸に手前へ開く。札は鍵を回したときにくるっと揺れる。回るのはオレンジの縁取りの内側の板だけで、縁取りは棚のものとして動かない(開いたデザインでも縁取りは箱の側にあり、扉の蝶番は板の右端にある)。板は蝶番のまわりに 3D で回し、開いたデザインの5枚の扉から求めたカメラ(`CAMERA`: 目の位置 300,1100・距離 3000 px、開いた角度 113 度。板の大きさで回して合わせたもの)から見た形にする。開いたデザインとのわずかな差は、開くにつれてなめらかに足す。90度までは閉じた板の表(鍵と札つき)、そこからは開いたデザインの扉(札つき)を射影変換(matrix3d)で貼るので、開き切ったときに写真と完全に重なる(切り替えのフェードはない)。開いた扉そのものをタップしても閉じる。扉の厚み(扉の幅の5%)は開く側の辺の外側に、厚み × sin(角度) の幅の帯で描く(90度までは左、そこからは右。真横で一番太い)。開いたデザインの扉には縁が見えないので、95度から開き切るまでに消す。鍵は閉め始めに元の向きに戻す。閉じた写真の札は、下の端がオレンジの縁取りに重なっていて、そこでは札と縁取りが同じような色になる。差だけで切り抜くとその帯が透けて札の下が切れて見えるので、札の本体は測った輪郭の形で切り抜き、扉の上に落ちた札の影は、明るさだけを落とす層(`tshadow`、暗い色＋透明度)として切り出し、扉と一緒に動かす(元の写真との差で切ると札の下に明るい縁が付くため)。扉が横を向くと、扉は暗くする層、鍵と札は brightness で同じだけ暗くする(暗くする層は扉の範囲しかないので、はみ出した札の先が明るい帯にならないように)。部品をまとめて縮める倍率は、丸められない計算済みの幅(`getComputedStyle(box).width`)で求める(`offsetWidth` は整数に丸められ、写真から1pxほどずれる)。札とその影は箱の下の段まで少しはみ出しているので、札は箱の下 20px まで切り抜き、扉が動いている間は影を消した画像(`under`。札の幅の範囲だけ。写真そのものの細かい線はそのまま残し、なめらかな明るさだけを影のすぐ右の色に置きかえるので、下の段の縁取りはずれない。下と左右の境目はぼかす)を箱の下にかぶせ、扉が 30 度開くまでに少しずつ濃くする。開いたデザインの札は、閉じた写真との差がはっきりある所だけを切り抜く(背景が四角く残らないように)。開いたデザインの扉の画像は3つに分ける: 扉そのもの(`opened`、扉の四隅に合わせて変形)、扉の端にぶら下がる鍵と札(`hang`、変形せず縦向きのまま扉の端の同じ位置について動く。真横の前後 84〜92 度で扉の表の札と入れ替わる)、扉が右の壁に落とす影(`wallshadow`、境目をぼかして取り込み、棚の右端より外は含めない。壁のものなので動かさず、90 度を過ぎて扉の端が右へ出ていくのに合わせて蝶番側から順に現れる)。ぶら下がる札は、開いたデザインの札の輪郭と鍵の円を手で測って切り抜く(色や差だけで取ると、すぐ後ろの縁取りや壁が一緒に動いてしまうため)。札や影を扉と一緒に変形すると、閉じていくときに札が縮んで切れたように見え、影に写った隣の私書箱がゴーストのように動いてしまうため。もう一度タップで同じ道筋を逆に閉まり(パタン)、鍵が戻る。店内の画像は Figma の node 344-2、開いた見た目は node 365-240。どちらも暗号化された中身に入っている(`locker-part`: door/key/tag は閉じた写真から、inside/opened は開いたデザインから切り出す)。位置は `works.html` の `LOCKERS`(画像 1116×2000 での座標)。

- 画面と操作: `works-dial.js`、`works.html` の `.dial-*`
- 画像: `dial-bed.webp`（写真の盤から穴だけを消した土台。外周の縁・厚み・紙のまわりは写真のまま）、`dial-shadow.webp`（穴の奥の影、回る）、`dial-rim-mask.png`（穴の縁と、穴の間の板の形。回るマスク。板は薄く光らせて、暗い穴との差を出す）、`dial-rim-tex.webp`（縁と壁の色。写真の光を画面に固定して使う）、`dial-hole-mask.png`・`dial-plate-mask.png`（穴の奥の壁。穴の形と、画面の下へずらした板の形の重なり）、`dial-top.webp`（固定の紙と指止め）
- 回るのは穴の形だけで、光や厚みは回らないので、回しても二重にならない。穴は等間隔。盤の楕円は写真の盤の表面（中心 566,1355・半径 80×53）
- 回る部分（影・縁・穴の奥の壁）は `works-dial.js` の `draw()` が canvas に描く。CSS のマスクと入れ子の変形では、iPhone の Safari で壁が穴の下側に出たため
- 部品の位置は `.works-scene`（写真と同じ縦横比の箱）に対する割合。スマホで画面の高さが足りず枠が縦に短くなっても、写真と部品は一緒に上下を切られるのでずれない
- `works-closed.webp` にも同じ盤を合成してある（溶ける演出の間も同じ見た目にするため）
- 暗号文: `assets/works.enc.json`（AES-256-GCM、鍵は PBKDF2-SHA256 60万回）

番号はリポジトリに置かない。ページは入力された番号で復号を試し、成功したときだけ中身を表示する。

## 中身や番号を変えるとき

1. `private/works-content.html`（git の対象外）を編集する。
2. 暗号文を作り直す: `WORKS_PASS=番号 python3 tools/encrypt-works.py`（`cryptography` が必要）
3. `works-dial.js` の `works.enc.json?v=` を上げる。

`private/` はこのパソコンにしかない。消えた場合は中身を作り直す。

## 調整する場所

| やりたいこと | 変更箇所 |
|---|---|
| 穴の位置の判定 | `works-dial.js` の `HOLES` |
| 指止めまでの角度 | `FIRST_TRAVEL` |
| 戻る速さ | `RETURN_SPEED` |
| 入力した桁の点 | `.dial-dots`（桁数の半分ずつ2行に並ぶ。電話を拡大してから表示） |
| 話し中の音 | `busyTone()` |
| 拡大の大きさ | `works.html` の `.phone-zoom .works-scene` の `scale(2.4)` |
| 電話のタップ範囲 | `works.html` の `.phone-tap` |

## 守りの強さ

8桁の数字は組み合わせが1億通りしかなく、暗号文は公開されているので、
時間をかけた総当たりには耐えられない。守秘義務のある内容はここに置かない。

## 店内の私書箱の素材（2026-11-05 作り直し）

継ぎはぎをなくすため、Figma から書き出した素材で作り直した。
- 鍵と札のない店内の画像（閉じた扉・縁取り・つまみ）を土台にし、扉の板・縁取り・札の下は、この画像をそのまま切り出す（描き直しはしない）。
- 鍵と札は、白地に鍵と札だけを置いた画像から切り抜く（白からの距離で透明度を求め、白を混ぜる前の色に戻す）。3段目と4段目は鍵がつまみより 10〜14px 上にあったので、つまみに合わせて下げる（`DY`）。札の影は鍵と札の画像に一緒に描き込み、札と一緒に揺れる。
- 店内の画像は、この土台に鍵・札・影を重ねたもの。
- 開いた扉の右の壁の影は、開いたデザインとその閉じた画像の明るさの比だけを取り出して土台に掛ける（別の画像の細部を持ち込まない）。範囲はその私書箱の段の中だけで、扉と札の部分は除く。
- 店内では、画像も部品も、写真と同じ縦横比の箱に上から合わせて置く（枠と写真の縦横比がわずかに違い、中央合わせだと 1px ずれるため）。
